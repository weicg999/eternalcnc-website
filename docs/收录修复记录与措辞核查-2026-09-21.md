## 一、域名规范：已统一为裸域 `https://eternalcnc.com`（commit `5f4d583`）

### 问题（原本的 P0）
全站 canonical / og:url / hreflang / sitemap 声明 `www.eternalcnc.com`，而 Cloudflare 边缘实际把 `www` 301 到裸域 → **闭环矛盾**：

```
canonical 说「正版是 www」  →  访问 www 被 301 到裸域  →  裸域页面又说「canonical 是 www」
```

代价：每页多一跳、抓取预算翻倍、权重拆到两个主机名、**IndexNow / 百度主动推送提交的 www URL 一进门就被 301 掉**。

### 改法：站点侧对齐裸域（不动 Cloudflare）
- `astro.config.mjs` 的 `site` → `https://eternalcnc.com`
  （canonical / og:url / hreflang **全部由 `Astro.site` 派生**，改这一行即翻全站）
- 硬编码绝对 URL 同步：JSON-LD 的 `url | logo | image`、`BaseLayout` 的 `orgSchema`、`qr.astro` 的 `TARGET_URL`
- `public/robots.txt` 的 Sitemap 声明；`public/_redirects` 说明块重写
- `scripts/indexnow-push.mjs` 的 `HOST`、`scripts/gen-sitemap.mjs`、`baidu_push.py` 的 `SITE`、`baidu-push-urls.txt`（149 条）
- `scripts/generate-news-reports-v2.py` 报表里的报价链接；名片/打印件与相关文档同步
- **共 262 处，涉及 84 个文件**

### 刻意保持不动
- `functions/` 的 **CORS 白名单同时保留裸域与 www**（防御性，避免误伤直连 www 的旧页面）
- `public/_redirects` 里已写明：**以后不要再把 Cloudflare 规则改成「裸域 → www」**，否则又反过来打架

### 线上实测（14:33）
| 检查 | 结果 |
|---|---|
| `sitemap-0.xml` | **303 条，含 www 0 条** ✔ |
| apex 首页 canonical / og:url | `https://eternalcnc.com/` ✔ |
| `robots.txt` 的 Sitemap 声明 | 裸域 ✔ |
| `https://www.eternalcnc.com/` | 301 → `https://eternalcnc.com/` ✔ |
| `https://www.eternalcnc.com/equipment/cato-ct80/` | 301 → **同路径**裸域（路径保留）✔ |
| `http://eternalcnc.com/` | 301 → `https://eternalcnc.com/` ✔ |

> 现在 `www → 裸域` 是**唯一的规范跳转**，正是搜索引擎期望的形态；闭环消失。
> （`http://www.` 走两跳：先升 HTTPS 再转裸域。想压成一跳可在 Cloudflare 加一条
> `http://www.eternalcnc.com/* → https://eternalcnc.com/$1`，非必需。）

## 四、病句俄语 3 处

上一轮「清外协措辞」做了**盲目字符串替换**——名词换了、没管性数格，读出来是「我们的 工厂 车间」。

|---|---|---|
| `ru/equipment/taikan-t500s` | `Входя в состав нашей завода цехов` | `Входя в состав нашего цеха` |
| `ru/equipment/taikan-tv1270s` | `Несколько станков работают на нашем заводе цехов` | `Несколько станков работают в нашем цехе` |
| `ru/equipment/wanghui-xh540` | `В нашей завода цехов XH-540 служит…` | `В нашем цехе XH-540 служит…` |
